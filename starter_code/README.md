1. Did performance improve after parallelization?Ans  : Yes, the performance improved after parallelizing both the 'scale_vector` and `sum_vector'  functions. The execution time was reduced because the work was divided among multiple threads, allowing tasks to run simultaneously.
2. Was the speedup linear?Ans : The speedup was close to linear for a limited number of threads. Ideally, increasing the number of threads should reduce execution time proportionally. However, in reality, the speedup is not perfectly linear due to factors like thread management overhead. As more threads are added, the improvement in performance gradually decreases.
3. Why did the naive parallel sum fail? Ans : The naive parallel sum approach failed because of a race condition. Multiple threads tried to access and update the shared variable `sum' at the same time without proper synchronization, which resulted in incorrect computations.
4. What limits the speedup?Ans : There are several factors that limit the speedup, but the main ones are:                                                                              1. Thread Overhead : Extra time is required to create, manage, and coordinate threads. In some cases, this overhead can reduce the overall performance gain.
       2. Thread Contention :  When the number of threads exceeds the available CPU cores, the processor has to switch between threads. This context switching increases execution time and reduces efficiency
